# UI review: Download, Library and Follow (2026-11-07)

This review covered the web GUI's three main flows: downloading to the browser ("Download"), downloading to the NAS library ("Library"), and Follow, which feeds automatic downloads. Each flow was traced through `frontend/src/App.tsx`, `src/gui_api.py` and `src/ruvsarpur.py`. **Status:** the HIGH items and the temp-file sweep were fixed in S1 (commits `cbd2620` and `212bf1c`, 2026-11-07) and are checked off below, with any differences from the suggested fix noted. The MEDIUM and LOW items are still open.

**Evidence grades:**
- *Reproduced*: run locally and seen to fail.
- *Measured*: checked in the browser at http://localhost:5173.
- *Predicted*: read from the code.

Line numbers are from commit `648519d`.

## Ranked by user impact

### HIGH: broken or misleading

- [x] **A browser download stops Library and Follow from ever downloading that episode.** *(Reproduced. Fixed differently: browser downloads pass `--norecord`, and explicit Library downloads pass `--ignorerecorded`, so they skip only files already in the library. A library job fails unless its file exists. A stopped download no longer leaves a truncated file, because ffmpeg writes to `.part`.)*
  - **Where:** `src/gui_api.py:893` (web mode adds `--force`), `src/ruvsarpur.py:1833` (the pid is recorded anyway), `frontend/src/App.tsx:1888`.
  - **What happens:** the downloader writes every downloaded pid to the shared `prevrecorded.log`. A later Library job or automatic run skips pids in that log, exits 0, and the queue shows "Download completed successfully". No file reaches the library.
  - **Repro:** web mode, then library mode for pid `bfcj7b`. The second run prints "already recorded" and the library folder stays empty.
  - **Fix:**
    - Add a `--norecord` flag to `ruvsarpur.py` and pass it in web mode.
    - When a library job finishes, check that a file was produced. If not, fail with: "Already marked as recorded, but no file is in the library. Retry to download it again."
    - The "Downloaded" badge (`isDownloaded`, `gui_api.py:858`) then means "in the library".

- [x] **Saving Settings overwrites the watchlist.** *(Predicted)*
  - **Where:** `frontend/src/App.tsx:589` posts the whole `settings` object, including `watchlistSids`. `src/gui_api.py:559` (`update_settings`) accepts it.
  - **What happens:** a stale tab, or a second user, wipes follows made elsewhere, with no message.
  - **Fix:** post `const { watchlistSids, ...rest } = settings`, and make `update_settings` ignore `watchlistSids`. The watchlist has its own endpoint.

- [x] **Finished browser downloads go to whichever tab checks first, and fire again on every reload.** *(Predicted)*
  - **Where:** `frontend/src/App.tsx:789-799` loops over all completed web jobs. Handled ids are kept only in that tab's memory (`handledDownloadJobsRef`). Download links are single-use (`gui_api.py:531`).
  - **What happens:**
    - Another user's tab can take your file, and your browser then gets a 404.
    - After a reload, every finished job fires a dead download again.
    - Nothing tells the user to keep the tab open.
  - **Fix:**
    - Generate a per-browser client id, keep it in `localStorage`, and send it with each `POST /api/download`.
    - Only save jobs that carry your own client id.
    - Keep the handled job ids in `localStorage`.
    - Dialog copy: "Keep this tab open; the file is saved when the download finishes."

- [x] **Follow does nothing while automation is off, and nothing says so.** *(Predicted; automation is currently off on the NAS. Fixed with one banner under the header on every page, not a notice next to each Follow control.)*
  - **Where:** `frontend/src/App.tsx:1261-1281`, `1488-1507` and `1733-1744`.
  - **Fix:** while automation is off, show "Not downloading: automation is off. Turn on" next to Following, linking to Settings. Alternatively, offer to turn automation on at the first Follow.

- [x] **The "N followed" counter counts episodes, not series.** *(Reproduced: following Veður showed "1377 followed")*
  - **Where:** `frontend/src/App.tsx:458` and `1090`.
  - **Fix:** use `settings.watchlistSids.length`.

- [x] **Poster tiles can only be opened with a mouse.** *(Measured: `tabIndex -1`, no link; WCAG 2.1.1)*
  - **Where:** `frontend/src/App.tsx:1462-1466` (`<li onClick>`).
  - **What it blocks:** the details page is the only place with the per-episode Download and Library buttons.
  - **Fix:** wrap the poster and title in react-router's `<Link to={`/title/${sid}`}>` and remove `onClick` from the `<li>`.

- [x] **The poster Follow button is invisible when it has keyboard focus.** *(Measured: opacity 0 while focused; WCAG 2.4.7)*
  - **Where:** `frontend/src/App.tsx:1482-1485`.
  - **Fix:** add `group-focus-within:opacity-100`.

- [x] **The download and Settings dialogs aren't real dialogs.** *(Measured: focus stays on `BODY`, Escape does nothing; WCAG 2.4.3 and 4.1.2)*
  - **Where:** `frontend/src/App.tsx:1559-1567` and `1683-1691`.
  - **What happens:**
    - Screen readers aren't told a dialog opened.
    - The page behind stays focusable.
    - The dialog sits after the whole page in tab order.
  - **Fix:** use a native `<dialog>` opened with `showModal()`, and return focus to the trigger on close.

- [x] **The page breaks at 320px.** *(Measured: 496px of content, a 24px search box, Refresh off-screen; WCAG 1.4.10)*
  - **Where:** `frontend/src/App.tsx:975` (fixed `w-44` sidebar) and `1019` (header doesn't wrap).
  - **Fix:**
    - Narrow the sidebar to icons below `md`: `w-14 md:w-44`, with labels `sr-only md:not-sr-only`.
    - Add `flex-wrap` to the header.

- [x] **Text contrast fails.** *(Measured; WCAG 1.4.3 needs 4.5:1)*
  - **Failing pairs:**
    - `text-slate-500` secondary text on the dark panels: 3.61:1 at 12px, 3.81:1 at 14px. 27 uses, for example `App.tsx:1347`, `1421`, `1611`, `1628`, `1712`.
    - White on `sky-600` buttons: 4.02:1 (`1644`, `1670`, `1724`).
    - `sky-50` on `sky-600/90` Download buttons: 4.38:1 (`1108`, `1298`, `1358`, `1430`).
  - **Fix:** `text-slate-400` for secondary text and `bg-sky-700` for the buttons, then remeasure.

- [x] **Animations ignore the reduced-motion setting.** No `motion-safe` or `prefers-reduced-motion` exists anywhere in the project.
  - **Where:** `frontend/src/App.tsx:1464` (`hover:-translate-y-0.5`), `1472` (`group-hover:scale-105`), `1114` (`animate-spin`).
  - **Fix:** add the `motion-safe:` prefix to each.

### MEDIUM

- [ ] **Unfollow happens in one click with no undo.**
  - **Where:** `frontend/src/App.tsx:1265`, `1400` and `1492`.
  - **What happens:** "Following" unfollows immediately. Only a red hover colour warns, so touch and keyboard users get no warning at all.
  - **Fix:**
    - Add `aria-pressed`.
    - Show the label "Unfollow" on hover and focus.
    - After unfollowing, show "Stopped following {title}. Undo".

- [ ] **The main action can't be chosen per person.**
  - **Where:** `frontend/src/App.tsx:1294-1307`, `1325-1326`, `1354-1367` and `1426-1439`.
  - **What happens:** "Download" is always the filled main button and "Library" the secondary. Some people mostly download to their computer; the owner mostly uses Library.
  - **Fix:** add a per-browser setting, "Main action on this computer: Download / Library", stored in `localStorage`. It decides which button is filled and comes first.

- [ ] **There's no list of followed series, and new seasons are missed.** *(Predicted; see "Scheduling downloads" in the README)*
  - **Where:** the Settings modal (`App.tsx:1683-1841`), `gui_api.py:703` (follows by `--sid`) and `gui_api.py:857`.
  - **What happens:**
    - Follows on series that have left the catalogue can't be seen or removed.
    - A new season can get a new sid, so it silently stops downloading.
  - **Fix:**
    - Add a "Following" list to Settings: title plus Unfollow, expired series included.
    - Consider following by title, which is what the README recommends for new seasons.
    - Until then, label the button "Follows this season only".

- [ ] **Unsaved Settings edits linger after closing.**
  - **Where:** `frontend/src/App.tsx:1741`, `1686` and `1627`.
  - **What happens:** the Automation toggle and folder fields only change local state. "Automation enabled" can show while the server still has it off, and the Library dialog shows unsaved paths.
  - **Fix:** save the automation toggle immediately. Discard or flag unsaved edits when Settings closes.

- [ ] **The Settings fields have no labels.** *(WCAG 3.3.2)*
  - **Where:** `frontend/src/App.tsx:1765-1826`.
  - **What happens:** each field's only label is its placeholder, so once filled, the Shows, Movies and Sports folder fields and the interval field look identical.
  - **Fix:** a visible `<label>` above each input.

- [ ] **Status and error messages aren't announced to screen readers.**
  - **Where:** `frontend/src/App.tsx:1209-1218`.
  - **Fix:** render empty `role="status"` and `role="alert"` regions up front, and update their text.

### LOW

- [ ] **Badges use `text-[10px]`**, below the 12px floor (`App.tsx:275-278`).
- [ ] **"episode(s)" should be a real plural** (`App.tsx:1258` and `1394`). Use `Intl.PluralRules`.
- [ ] **The per-button download progress bar is dead code.** `startDownloadTicker` is never called (`App.tsx:460-486`, plus the bar spans at `1300`, `1360` and `1432`). Delete it.
- [ ] **The page says `lang="en"` although titles and descriptions are Icelandic** (`frontend/index.html:2`). Mark the Icelandic content with `lang="is"`.

## Outside the UI

- [x] **Temporary files for browser downloads are never deleted.** *(Fixed: folders are kept 24 hours so links can be reused, then swept at startup and hourly.)*
  - **Where:** `downloads/_web_tmp/<job>`, set at `gui_api.py:147`. Nothing removes it.
  - **Impact:** on the TrueNAS deployment this sits on the 256 GB support NVMe, at 1–2 GB per episode.
  - **Fix:** delete a job's temp folder once its file has been served, and sweep folders older than a day at startup.
